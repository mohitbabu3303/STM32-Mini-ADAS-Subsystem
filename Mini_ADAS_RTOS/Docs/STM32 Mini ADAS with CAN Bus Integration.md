# STM32 Mini ADAS with CAN Bus Integration

## Overview

This project demonstrates a professional automotive embedded systems design for an **Advanced Driver Assistance System (ADAS)** using an STM32F103 microcontroller with **CAN bus communication**, **FreeRTOS real-time task scheduling**, and modular architecture suitable for automotive ECU development.

## Key Features

### 1. FreeRTOS Task Architecture

The system implements a professional RTOS task structure with seven concurrent tasks:

- **SensorTask** (Priority: Normal): Simulates sensor data generation (lane status, obstacle distance)
- **DecisionTask** (Priority: Above Normal): Processes sensor data and generates alerts
- **CAN_TxTask** (Priority: Normal): Transmits ADAS data over CAN bus
- **CAN_RxTask** (Priority: Normal): Receives and processes CAN messages
- **LoggerTask** (Priority: Low): Logs system events to UART
- **DashboardTask** (Priority: Low): Prepares data for external visualization
- **HealthMonitorTask** (Priority: High): Monitors system health and error states

### 2. CAN Bus Communication

The CAN module provides automotive-grade communication:

- **Standard CAN (11-bit identifiers)** at **500 kbps** baud rate
- Three message types: Sensor Data (0x100), Decision Alerts (0x200), System Status (0x300)
- Hardware message filtering for selective reception
- Interrupt-driven message handling via RX FIFO0
- Professional message structure definitions in `can_messages.h`

### 3. Message Queue Synchronization

FreeRTOS message queues enable safe inter-task communication:

- `sensorQueue`: Carries sensor data from SensorTask to DecisionTask
- `alertQueue`: Carries alert data from DecisionTask to LoggerTask

### 4. ADAS Logic

The decision engine implements basic ADAS algorithms:

- **Lane Departure Warning**: Detects lane status changes
- **Obstacle Detection**: Alerts when obstacles are within 20 meters
- **Risk Assessment**: Evaluates threat level based on sensor inputs

## Hardware Integration

### Microcontroller
- **STM32F103C8TX**: ARM Cortex-M3, 72 MHz, 64 KB RAM, 256 KB Flash

### Peripherals
- **UART1**: 9600 baud for debugging and logging
- **CAN1**: 500 kbps for ECU communication
- **GPIO**: PA5 for status LED

### CAN Transceiver (for real hardware)
- **MCP2551** or **TJA1050** or **SN65HVD230**
- CAN_H and CAN_L twisted pair with 120-ohm termination

## Software Stack

- **Compiler**: GCC ARM (arm-none-eabi-gcc)
- **IDE**: STM32CubeIDE
- **HAL**: STM32F1xx HAL Driver
- **RTOS**: FreeRTOS v10.x
- **Protocol**: CAN 2.0B

## Building and Flashing

### Prerequisites
- STM32CubeIDE installed
- ST-Link debugger connected
- Mini_ADAS_RTOS.ioc file for configuration

### Build Steps

1. Open `Mini_ADAS_RTOS.ioc` in STM32CubeMX
2. Generate code (Project → Generate Code)
3. Build in STM32CubeIDE (Project → Build All)
4. Flash to STM32 (Run → Debug)

## Simulation and Testing

The project operates in **software simulation mode** without requiring real hardware:

- Sensor data is randomly generated by SensorTask
- CAN messages are processed through the HAL layer
- All ADAS logic executes in real-time with FreeRTOS scheduling
- UART output shows system activity and alerts

### Expected Output

```
Sensor Sent -> Lane:1 Dist:15
ALERT: Lane Deviation!
ALERT: Obstacle Too Close!
CAN Rx: ID=0x100, Data=[1 15 0 0 0 0 0 0]
```

## Real Hardware Challenges

When deploying to actual hardware, engineers must address:

1. **CAN Transceiver Wiring**: Proper impedance matching and shielding
2. **Signal Integrity**: Noise filtering and EMI/EMC compliance
3. **Timing Jitter**: Real-time constraints under interrupt load
4. **Sensor Calibration**: Accurate distance and lane detection
5. **Debugging**: Using oscilloscopes, logic analyzers, and CAN analyzers
6. **Power Supply Noise**: Stable voltage for analog sensors
7. **Thermal Management**: Operating temperature ranges
